# Domain docs

## Before exploring

Read the root `CONTEXT.md` and relevant decisions in `docs/adr/`.

If these files do not exist, proceed silently. The domain-modeling
skill creates them lazily as terms and decisions are resolved.

## Layout

This repository uses a single context:

- `CONTEXT.md`: domain vocabulary and model.
- `docs/adr/`: numbered architecture decision records.

## Vocabulary and decisions

Use the glossary's terms when naming domain concepts in issues,
proposals, hypotheses, and tests.

If a needed concept is missing, reconsider the terminology or note
the gap for domain-modeling.

Explicitly flag proposals that contradict an existing ADR, identify
the ADR, and explain why the decision should be reconsidered.
